# Online Search task pipeline

This branch builds, validates, calibrates, and optionally publishes current
Online Search tasks. It uses DeepSeek V4.1 Flash at xhigh reasoning for the
builder and judge, the normalized twelve-file task contract, a strict Oracle
gate, and the production Muse solver regime.

## Publication contract

Every published task contains exactly twelve files:

```text
instruction.md
task.toml
environment/Dockerfile
solution/evidence_graph.json
solution/report.md
solution/solve.sh
tests/Dockerfile
tests/rubrics.json
tests/test.sh
tests/test_outputs.py
tests/test_utils.py
tests/reference/ground_truth.json
```

The seven runtime and verifier files come from `canonical/` and are restored
byte for byte around authoring. The builder owns only the instruction, report,
rubric, ground truth, and evidence graph. The solver writes only
`/app/output/report.md`. Source manifests, Docker Compose files, duplicate
graphs, decision logs, checked-in bytecode, traces, and marker files are not
part of a task package.

The task contract and production Muse trials both use a 10,800-second solver
timeout. The verifier timeout remains 1,600 seconds and begins only after the
solver process has produced its preserved deliverable.

The instruction is a coherent request from a domain-appropriate person, not
benchmark metadata. It is at most 350 words, uses ASCII outside URLs, requires
live public-web research and exact inline citations, and avoids source lists,
domain restrictions, answer leakage, scoring guidance, em dashes, artificial
data overload, and unnecessary cutoff dates.

## Domain taxonomy

`domain-taxonomy.yaml` is the single production allowlist for task domains.
The pipeline validates the selected seed against it before assigning a task ID,
copying a template, or calling any model. Unknown labels fail closed. Law,
Public Policy, Environment, and Climate labels and their listed aliases are
explicitly rejected.

The default `ideas.yaml` and `ideas-reserve.yaml` are generated by
`scripts/build_taxonomy_catalog.py`. It removes excluded-domain seeds and
source-hint/cutoff metadata, then orders the accepted ideas round-robin by
domain so the start of a campaign is not dominated by one taxonomy category.
The same runtime gate applies to externally supplied idea files.

The reference report is a thorough, cited, decision-ready answer. Rubrics,
ground truth, and evidence graphs use the exact normalized schemas enforced by
`scripts/validate_live_task.py`. Rubric rows are atomic, binary, independent,
fair, and fully mapped. The report and graph contain no tier/role metadata or
decision-log language.

## Pipeline

1. Select a non-repeating idea and assign its stable three-word slug.
2. Instantiate `example-task/` and restore canonical files.
3. Author the five task-specific files with DeepSeek V4.1 Flash at xhigh.
4. Run an independent DeepSeek V4.1 Flash xhigh semantic massage for fairness,
   factual alignment, source support, formatting, and surgical repair.
5. Restore canonical files again and enforce the exact package and 350-word
   instruction limit.
6. Run structural, semantic-alignment, URL, schema, mapping, hash, and fairness
   validation in capture and verify modes.
7. Run the Agentic Verifier Oracle with DeepSeek V4.1 Flash xhigh and require a
   score strictly above 0.9.
8. Run three `meta-muse-spark` trials through the current `miniswe-muse`
   harness: xhigh reasoning, 10,800-second timeout, 700k context goal, 950k
   finish prompt, and 1,048,576-token hard limit.
9. Require three gradable trials, mean solver score below 0.8, and at least one
   trial with peak-call context at or above 500k. A 700k peak remains the target.
10. Remove builder state, revalidate the package offline, push, and open an
   `[online-search] <stable-id> <three-word-slug>` pull request.

The build-only benchmark variants stop after Oracle and package validation.
They do not launch solver trials or deploy.

## Runtime configuration

The default production config is `config.yaml`. The DSH/DSML comparison is
`config-online-search-pipeline-deepseek-dsh-dsml.yaml`; its build-only form is
`config-online-search-build-only-deepseek-dsh-dsml.yaml`.

Required secrets are read only from the environment and are never written to
task or trace artifacts:

- `OPENROUTER_API_KEY` for DeepSeek builder/judge access;
- `PARSEWAVE_TOKEN` or `MUSE_API_KEY` for the Launchpad Muse route.

Set `ONLINE_SEARCH_MUSE_HARNESS` to the current patched `miniswe-muse` checkout.
That checkout must expose `--finish-prompt-tokens`; the pipeline fails fast on
an older harness rather than silently running the wrong regime.

The DSH/DSML builder is likewise fail-closed on the validated
`builder/search-pipeline` source build at commit
`3a224bc69c3a3230272ed5750b30fe90d87b47fc`. Set
`ONLINE_SEARCH_DSH_SOURCE_ROOT` if that build lives outside the default
user-local install path. The npm release is not an automatic fallback.

`scripts/setup_agentic_verifier.sh` creates a separate pinned Agentic Verifier
install from commit `145eba926c53e7ecb1b112c5b021064308ff6536` plus the reviewed
Online Search graph and DeepSeek-transport compatibility patch. Solver reports
are graded there after the Muse process exits, never by the solver itself.
Set `VERIFIER_SEARCH_URL` to the online search gateway (default
`http://127.0.0.1:18120`).

Example:

```bash
export DORAEMON_IDEA_SOURCE=/absolute/path/to/ideas.yaml
export ONLINE_SEARCH_MUSE_HARNESS=/absolute/path/to/miniswe-muse-fleet
./run.sh --config config.yaml --count 10 --concurrency 4 --conc-trials 12
```

## Validation

For a staged task:

```bash
python3 scripts/validate_live_task.py \
  --task-root /absolute/path/to/task \
  --task-id three-word-slug \
  --mode package
```

`capture` and `verify` also check public URLs. Repeated 404/410 responses are
hard failures. Authentication barriers, rate limits, and transient network
errors are reported but are not mislabeled as dead sources.

Repository checks:

```bash
uv run pytest
uv run ruff check .
```
